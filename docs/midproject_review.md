# Mid-Project Review

## Learning Objectives

By completing this assignment, students should be able to:

* Practice professional software engineering workflows
* Communicate effectively with stakeholders and research advisors
* Translate feedback into actionable development tasks
* Use GitHub Issues to organize project work
* Develop and test meaningful software features
* Properly merge and document completed work
* Professionally demonstrate and explain technical progress

## Part 1 — Research Advisor Meetings and Issue Creation (2 Marks)

Each group must contact their assigned research advisor prior to the Mid-Project Review presentation.

The purpose of this meeting is to:

* Discuss project progress
* Receive technical or strategic feedback
* Clarify project direction
* Identify challenges and proposed solutions
* Define what should be completed by the mid-project revire presentations

### Required Deliverables

After meeting with the research advisor, groups must create GitHub Issues, following our course's template, documenting the work that needs to be done.

### Evaluation Criteria

To receive full marks:

* The group must demonstrate meaningful communication with their advisor
* Issues must clearly reflect the discussion that took place
* Issues must be properly structured and professionally written
* Issues must be actionable and technically relevant

## Part 2 — Implementation and Testing (10 Marks)

Each student must work on the issues created from the advisor meeting and implement meaningful progress toward their CAPSTONE project prototype.

The work completed must demonstrate:

* Technical progress
* Appropriate software engineering practices
* Proper testing strategies

### Required Expectations

Students are expected to:

* Implement meaningful features
* Follow proper Git workflows
* Use branches and Pull Requests
* Write appropriate automated tests when applicable
* Maintain professional repository organization

### Testing Expectations

Students must provide evidence of testing relevant to the work completed.

Examples include:

* Unit tests
* Integration tests
* API tests
* CI/CD validation workflows

### Important Notes

Simply creating interfaces or placeholder code without meaningful functionality may result in reduced marks.

## Part 3 — Merge, Documentation, and Issue Closure (2 Marks)

Once work has been completed, groups must properly merge their work into their production branch (`main` or equivalent).

Students are expected to follow professional Git workflows.

### Required Tasks

Students must:

* Create Pull Requests
* Merge completed work into `main`
* Close completed GitHub Issues
* Link Pull Requests to Issues
* Update project documentation

### Required Documentation Updates

Examples may include:

* `CHANGELOG.md`
* `README.md`
* API documentation
* Setup instructions
* Testing documentation
* Deployment instructions

## Part 4 — Mid-Project Review Presentation (6 Marks)

Students from each group will present their prototype and discuss the work completed during this milestone.

The presentation should focus on:

* What was accomplished
* Technical challenges encountered
* Testing strategies used
* Next development goals

### Presentation Expectations

Groups should demonstrate:

* The current state of their prototype
* Functional features
* Relevant testing workflows
* Repository organization
* CI/CD or automation when applicable

Students should be prepared to answer technical questions related to:

* Architecture
* Design decisions
* Testing approaches
* Git workflows
* Deployment strategies

### Suggested Presentation Structure

#### 1. Project Overview

Briefly explain:

* The purpose of the project
* Main features

#### 2. Advisor Feedback

Discuss:

* What was discussed with the research advisor
* Key recommendations received
* How the team responded to feedback

#### 3. Demonstration of Prototype

Demonstrate:

* Implemented features
* Current workflows
* Functional prototype components

#### 4. Testing and Quality Assurance

Explain:

* Tests implemented
* CI/CD workflows
* Quality assurance strategies

#### 5. Challenges and Next Steps

Discuss:

* Technical challenges
* Remaining milestones
* Planned future development

## Submission Requirements

Prior to the Scrum presentation, groups must ensure that:

* All relevant GitHub Issues are updated
* Pull Requests are merged
* Documentation is updated
* Tests are committed to the repository
* The repository reflects the latest project milestone

## Evaluation Breakdown

| Component                                      | Marks        |
| ---------------------------------------------- | ------------ |
| Research Advisor Discussion and Issue Creation | 2            |
| Implementation and Testing                     | 10           |
| Merge, Documentation, and Issue Closure        | 2            |
| Mid-Project Review Presentation                | 6            |
| **Total**                                      | **20 Marks** |

Note that only the first component is group based. All other components will be marked on an individual basis.
